# Codex D2C 상세 사용 설명서

대상: 이 PC에서 여러 네이버 스마트스토어와 SNS 게시를 관리하고 Codex로 마케팅 자료를 만드는 운영자.

작업 폴더는 `C:\dev\dev\d2c\codex_version`, 기본 주소는 [http://127.0.0.1:4317](http://127.0.0.1:4317)입니다. 기준 버전은 0.5.0입니다.

## 프로그램과 Codex의 역할

| 위치 | 하는 일 |
|---|---|
| 로컬 운영 화면 | 연결, 수집, AI 동향 조사·캠페인 제작, 검토, Playwright 게시, 실제 URL 기록 |
| Codex SDK worker | ChatGPT 구독 로그인으로 웹 동향 조사, 카피와 로컬 렌더링 이미지 제작 |
| Codex 채팅 | 예외 상황 점검, 수동 보완, 소스 수정 |
| SNS 전용 브라우저 | 로그인·추가 인증, 실제 게시 계정과 결과 확인 |

로컬 앱은 공식 Codex SDK를 통해 구독형 Codex를 실행합니다. OpenAI API 키 방식은 별도 과금을 피하기 위해 자동 작업에서 차단합니다. 최초 연결은 [구독 Codex AI 연결과 화면 실행](ai-automation.md)을 따릅니다.

## 실행과 재개

### 최초 설치

```powershell
Set-Location -LiteralPath 'C:\dev\dev\d2c\codex_version'
node --version
npm install
```

Node.js 24 이상을 확인한 뒤 `start.bat`을 실행합니다.

### PC 재부팅 뒤

1. 탐색기에서 `C:\dev\dev\d2c\codex_version`을 엽니다.
2. `start.bat`을 더블클릭합니다.
3. 화면이 자동으로 열리지 않으면 기본 주소를 직접 엽니다.
4. **오늘 할 일**의 상단 안내부터 실행합니다.

재부팅 뒤 `npm install`, 네이버 키 입력, SNS 로그인을 반복할 필요는 없습니다. 앱 서버만 다시 시작합니다. Instagram·Threads·밴드가 세션을 만료한 경우 해당 채널만 다시 로그인합니다.

### 새로고침의 의미

- Codex가 캠페인 결과를 저장한 뒤 화면에 반영
- 다른 창에서 바뀐 로컬 데이터를 다시 읽기
- 서버 재시작 뒤 새 요청 토큰 받기

새로고침은 네이버 수집, AI 생성, SNS 게시를 실행하지 않습니다. 편집 중인 내용은 먼저 저장합니다.

## 오늘 할 일 화면

앱의 기본 화면이자 운영 대시보드입니다. 상단 초록 카드에는 현재 가장 우선할 작업과 버튼 하나가 표시됩니다. 지표 카드는 연결 스토어, 판매 상품, 처리 대기 중인 Codex 요청, 게시 대기 캠페인 수를 보여줍니다. 마지막 정상 수집 후 24시간이 지나면 오늘의 작업에 갱신 항목이 나타납니다.

우선순위는 다음과 같습니다.

1. SNS 게시를 마쳤지만 실제 URL을 기록하지 않은 작업
2. 대기 중인 AI 제작 요청
3. 대기 중인 AI 동향 조사
4. 검토가 끝난 캠페인의 SNS 게시
5. 카피·이미지가 있는 캠페인의 상품 사실 검토
6. 제작 중인 캠페인 또는 네이버 연결·수집

**오늘의 작업**에는 실제로 처리할 항목만 표시됩니다. 아래 스토어와 SNS 영역에서 최근 수집 시각과 로그인 상태를 확인할 수 있습니다.

## 동향 조사와 광고 아이디어

1. **오늘의 화제 조사**, **이번 주 화제 조사** 중 하나를 누르거나 관심 키워드를 입력합니다.
2. AI가 자동으로 시작되지 않았다면 **AI 조사 시작**을 누릅니다.
3. Codex가 웹 출처와 발행일을 확인하는 동안 화면의 상태를 확인합니다.
4. 완료되면 결과가 자동 표시됩니다. 필요할 때만 오른쪽 위 **새로고침**을 누릅니다.
5. 동향 요약, 상품 연관도, 광고 아이디어, 활용 기간과 주의 사항을 확인합니다.
6. **이 아이디어로 캠페인 만들기**를 누르면 연결 상품, 추천 채널, 동향 근거가 새 캠페인 양식에 입력됩니다.

완료된 조사가 여러 개면 결과 위의 최근 조사 목록에서 오늘·이번 주·키워드 결과를 다시 선택할 수 있습니다.

조사 버튼은 로그인된 구독 Codex worker를 바로 실행합니다. 출처 링크와 발행일이 없는 결과는 저장할 수 없습니다. 뉴스의 주장과 상품의 가격·구성·효능을 섞지 말고 캠페인 생성 후에도 실제 판매 정보를 검토합니다.

## 네이버 스마트스토어 여러 개 연결

### 첫 연결 또는 추가 연결

1. **연결 · 채널**을 엽니다.
2. **네이버 스토어 추가**를 누릅니다.
3. 스토어 이름, 고유 식별자, Client ID, Client Secret을 입력합니다.
4. **연결 저장**을 누릅니다.
5. 네이버 커머스 API 센터에서 현재 PC 공인 IP와 조회 권한을 확인합니다.
6. 해당 스토어의 **지금 수집**을 누릅니다.

기존 0.2.x의 단일 `.env` 연결은 최초 0.3.0 실행 때 자동으로 첫 연결이 됩니다. 추가 스토어만 새로 등록하면 됩니다.

### 연결 수정과 사용 해제

스토어 카드의 **설정 수정**을 누릅니다. 이름과 키를 바꿀 수 있으며 키를 유지하려면 비워 둡니다. **이 연결을 사용합니다** 체크를 끄면 기존 상품·주문은 보존하고 전체 수집에서 제외합니다.

스토어 식별자는 상품과 주문의 내부 ID에 포함되므로 저장 후 수정할 수 없습니다.

### 개별·전체 수집

- 오늘 할 일 또는 연결 화면의 **전체 수집**: 사용 중인 모든 스토어
- 특정 스토어 카드의 **수집/지금 수집**: 그 스토어만
- 상품 보관함의 **네이버 상품 수집**: 선택한 필터 또는 전체의 상품
- 주문·수집 기록의 **주문 수집**: 선택한 필터 또는 전체의 주문

전체 수집에서 일부 연결이 실패하면 성공한 연결은 유지하고 실패 수를 알려줍니다. 주문·수집 기록에서 스토어 필터를 선택해 오류를 확인합니다.

## 상품 보관함

상품 카드에는 네이버 스토어 이름 또는 직접 등록 표시가 나옵니다. 상단 스토어 필터로 전체, 직접 등록, 특정 네이버 스토어를 선택합니다.

캠페인에는 `SALE` 상태 상품만 사용할 수 있습니다. 품절·판매 중지·목록 제외 상품은 보관하지만 새 캠페인 버튼이 비활성화됩니다.

네이버 연결 없이 시작하려면 **상품 추가**로 실제 상품명, 판매가, 사진 URL, 판매 URL, 확인된 상품 사실을 입력합니다.

## 캠페인 만들기

1. 상품 카드의 **이 상품으로 캠페인 만들기**를 누릅니다.
2. 캠페인 제목을 입력합니다.
3. 로그인 완료로 표시된 게시 채널을 하나 이상 선택합니다. 미연결 채널은 `로그인 필요`로 비활성화됩니다.
4. 대상 고객, 상황, 강조할 사실, 말투, 피할 표현을 제작 방향에 적습니다.
5. **캠페인 만들기**를 누릅니다.

게시 채널은 검토 전에 편집 화면에서 바꿀 수 있습니다. Threads를 선택하면 공통 본문을 500자 이하로 작성합니다.

동향 조사에서 Threads나 밴드를 추천해도 해당 채널이 로그인되지 않았다면 새 캠페인에는 선택되지 않습니다. **연결 · 채널**에서 로그인을 완료한 뒤 새 캠페인 창을 다시 열면 선택할 수 있습니다.

## Codex로 광고 제작

1. 제목·방향·채널을 수정했다면 **수정 내용 저장**을 누릅니다.
2. **AI 광고 제작 시작**을 누릅니다.
3. 생성·이미지 렌더링·저장 상태가 완료될 때까지 기다립니다. 다른 화면으로 이동해도 worker는 계속 실행됩니다.
4. 저장된 카피 시안 중 하나를 선택하거나 본문을 직접 편집합니다.
5. 이미지와 본문을 확정하고 **수정 내용 저장**을 누릅니다.

로그인 전에 누르면 제작 요청만 보관됩니다. **연결 · 채널**에서 ChatGPT 로그인을 완료한 뒤 오늘 할 일 화면의 실행 버튼으로 이어서 처리합니다. 구체적인 상태와 복구 절차는 [AI 자동화 문서](ai-automation.md)를 참고합니다.

이미지 파일 선택만으로는 캠페인 적용이 끝나지 않습니다. 반드시 저장 버튼을 누릅니다.

## 검토

본문·이미지가 모두 저장되면 검토 버튼이 활성화됩니다.

1. 상품 가격과 판매 상태가 현재 값과 같은지 확인합니다.
2. 구성·원산지·포장·배송·할인 문구를 실제 판매 페이지와 대조합니다.
3. 이미지가 상품의 모양·수량·사용 장면을 오해하게 하지 않는지 봅니다.
4. 선택 채널과 본문 길이를 확인합니다.
5. 확인란을 체크하고 **검토 완료로 표시**를 누릅니다.

검토 후 아직 게시 기록이 없으면 내용을 수정할 수 있지만 수정 시 제작 중으로 돌아갑니다. 한 채널이라도 실제 게시 URL을 기록하면 동일 확정본을 보호하기 위해 더 이상 편집하지 못합니다.

## SNS 연결

**연결 · 채널**에는 Instagram, Threads, 네이버 밴드 카드가 있습니다. 각 채널은 별도 로그인 프로필을 사용합니다.

1. **전용 브라우저 로그인**을 누릅니다.
2. 열린 창에서 로그인과 추가 인증을 직접 완료합니다.
3. 앱의 상태가 완료로 바뀌는지 확인합니다.

밴드는 게시할 밴드 홈 주소 `https://band.us/band/숫자`를 먼저 저장합니다. 자세한 내용은 [SNS 채널 로그인과 게시](social-channels.md)를 참고합니다.

## 채널별 게시와 URL 기록

검토 완료 캠페인에는 선택한 채널만 카드로 나타납니다.

1. 채널의 로그인 상태를 확인합니다.
2. 현재 내용이 해당 계정에 즉시 게시된다는 확인란을 체크합니다.
3. 채널의 **게시** 버튼을 누릅니다.
4. 자동화가 진행되는 동안 같은 버튼을 다시 누르지 않습니다.
5. 완료가 표시되면 실제 SNS에서 게시물을 확인합니다.
6. 실제 게시물 주소를 입력하고 확인란을 체크한 뒤 **주소 기록**을 누릅니다.

허용 URL 예:

- Instagram: `https://www.instagram.com/p/코드/` 또는 `/reel/코드/`
- Threads: `https://www.threads.com/@계정/post/코드/` 또는 `https://www.threads.com/share/코드/`
- 밴드: `https://band.us/band/숫자/post/숫자`

완료 메시지가 떴어도 URL 기록 전에는 같은 채널을 다시 게시하지 않습니다. 브라우저 작업이 실패하거나 중단됐다면 실제 계정부터 확인합니다.

## 주문과 수집 이력

주문 화면은 상품 주문 번호, 상품명, 수량, 결제 금액, 상태, 결제 시각, 스토어를 표시합니다. 수령인·주소·전화번호는 저장하지 않습니다.

첫 주문 수집은 최근 24시간 변경 내역을 조회하고, 이후에는 스토어별 마지막 성공 위치에서 이어받습니다. 표시된 변경 주문 건수는 신규 매출과 같지 않으며 취소·반품 같은 상태 변경도 포함될 수 있습니다.

## 백업과 종료

**연결 · 채널 → DB 백업 만들기**는 `data/backups`에 SQLite 백업을 만듭니다. 게시 이미지까지 보존하려면 `data` 폴더 전체를 복사합니다.

작업을 마치면 `stop.bat`을 실행합니다. 탭만 닫아도 서버는 남을 수 있습니다. `npm start`로 실행했다면 PowerShell에서 `Ctrl+C`로 종료합니다.

## 제한 사항

- 캠페인당 공통 본문 1개와 이미지 1장을 사용합니다.
- 캐러셀, 동영상, 릴스·스토리, 예약 게시, 유료 광고 집행은 포함하지 않습니다.
- 밴드 대상은 현재 기본 주소 1곳입니다.
- SNS 웹 UI가 바뀌면 자동화 선택자 수정이 필요할 수 있습니다.
- 로컬 앱은 `127.0.0.1` 전용이며 스마트폰에서 직접 접속하는 구조가 아닙니다.
