# 여러 네이버 스마트스토어 연결

[문서 목록](README.md) · [매일 운영 순서](daily-operation.md) · [문제 해결](troubleshooting.md)

## 연결 추가

1. **연결 · 채널**을 엽니다.
2. **네이버 스토어 추가**를 누릅니다.
3. 화면에 표시할 이름과 고유한 스토어 식별자를 입력합니다.
4. 해당 네이버 커머스 API 애플리케이션의 Client ID와 Client Secret을 입력합니다.
5. **연결 저장**을 누릅니다.
6. 커머스 API 센터에서 상품·주문 조회 권한과 현재 PC의 공인 IP를 확인합니다.
7. 새 스토어 카드에서 **지금 수집**을 실행합니다.

스토어 식별자는 `bada-main`, `gift_store`처럼 영문·숫자·밑줄·하이픈으로 만듭니다. 저장 뒤에는 상품·주문 ID와 수집 위치의 기준이 되므로 화면에서 바꿀 수 없습니다. 다른 식별자가 필요하면 새 연결로 추가합니다.

## 기존 단일 연결

0.2.x에서 `.env`에 저장했던 단일 연결은 0.3.0 서버가 처음 시작될 때 `data/d2c.sqlite`의 첫 번째 네이버 연결로 한 번만 이관합니다. 기존 상품 ID와 스토어 식별자가 유지됩니다. `.env` 파일을 지우거나 키를 다시 입력할 필요가 없습니다.

추가 연결의 자격증명은 로컬 SQLite에 저장합니다. `/api/state`와 화면에는 연결 여부·이름·식별자만 전달하며 Client ID와 Client Secret은 반환하지 않습니다. 공유 PC라면 Windows 계정과 디스크 접근 권한을 보호합니다.

## 수집 방식

- **전체 스토어 수집**: 사용 중인 모든 연결을 순서대로 수집합니다. 한 연결이 실패하면 나머지를 계속하고 실패 수와 연결별 이력을 남깁니다.
- **개별 수집**: 특정 카드의 **지금 수집** 또는 오늘 할 일의 **수집**을 누릅니다.
- **화면 필터**: 상품 보관함과 주문·수집 기록에서 전체 또는 특정 스토어를 선택합니다.
- **일시 제외**: 스토어 설정 수정에서 사용 체크를 끕니다. 기존 데이터는 삭제하지 않고 전체 수집 대상에서만 제외합니다.

각 연결은 다음 값을 독립적으로 사용합니다.

- 상품 ID: `naver_<스토어식별자>_<원상품번호>`
- 상품 주문 ID: 스토어 식별자가 포함된 ID
- 주문 체크포인트: `naver:cursor:<스토어식별자>`
- 수집 잠금과 실행 이력: 스토어별 분리

따라서 두 스토어에 같은 네이버 원상품 번호가 있어도 로컬에서 충돌하지 않습니다.

## CLI

```powershell
node src/cli.mjs naver-stores
node src/cli.mjs sync all
node src/cli.mjs sync products --store bada-main
node src/cli.mjs sync orders --store gift_store
node src/cli.mjs sync orders --store bada-main --from 2026-09-01T00:00:00+09:00
```

`sync all`은 사용 중인 모든 연결을 대상으로 합니다. `--store`를 지정하면 한 연결만 실행합니다. CLI 출력의 `naver-stores`에도 비밀키는 포함하지 않습니다.

## 연결별 문제 확인

전체 수집에서 실패가 표시되면 **주문 · 수집 기록**의 스토어 필터로 해당 연결을 선택합니다. 흔한 원인은 현재 공인 IP 미등록, 애플리케이션 권한 차이, 잘못된 키, 일시적인 네트워크 오류입니다. 키 값을 Codex 채팅이나 로그에 붙여넣지 않습니다.
