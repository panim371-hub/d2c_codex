# 상황별 문제 해결

[문서 목록](README.md) · [상세 사용 설명서](user-guide.md)

오류를 점검할 때는 사용한 화면, 누른 버튼, 표시된 오류 문구, 현재 네트워크를 함께 확인합니다. 네이버 키 저장·네이버 접속 성공·상품 수집·광고 제작은 각각 별도의 단계입니다.

## 운영 화면이 열리지 않아요

| 상황 | 확인 및 조치 |
|---|---|
| PC 재부팅 후 연결할 수 없음 | 탐색기에서 `C:\dev\dev\d2c\codex_version\start.bat` 실행 |
| 시작했는데 브라우저가 안 열림 | 같은 PC에서 `http://127.0.0.1:4317/` 직접 열기 |
| Node를 찾을 수 없다고 나옴 | PowerShell에서 `node --version` 확인. Node.js 24 이상 설치 후 다시 시작 |
| 먼저 npm install을 실행하라고 나옴 | `codex_version` 폴더에서 `npm install` 실행 |
| 포트를 사용 중이라고 나옴 | 기존 주소를 먼저 확인. 다른 프로그램을 임의로 종료하지 말고 Codex에 앱·포트 점검 요청 |
| 설정에서 포트를 바꿨음 | 기본 4317 대신 설정한 포트로 접속. `.env` 직접 변경은 서버 재시작 필요 |
| 휴대폰에서는 안 열림 | 현재 앱은 PC의 127.0.0.1에만 연결되므로 같은 PC에서 사용 |

서버 시작 실패 기록은 `C:\dev\dev\d2c\codex_version\data\runtime\server-error.log`에 있습니다. 로그 점검은 Codex에 요청할 수 있습니다. 실행 중인지 확인하지 않고 여러 Node 프로세스를 한꺼번에 종료하지 않습니다.

## 키를 저장했는데 상품이 0개예요

1. 상단 **네이버 N개 연결**은 사용 중인 키가 있다는 표시입니다.
2. **오늘 할 일 → 전체 수집** 또는 **상품 보관함 → 네이버 상품 수집**을 실행합니다.
3. **주문 · 수집 기록**에서 최신 이력의 결과를 확인합니다.
4. 실패라면 오류에 맞춰 다음 항목을 확인합니다.

상품 보관함에는 상품이 있지만 스튜디오가 0이면 판매 상태를 확인합니다. 스튜디오의 수는 `SALE` 상품만 집계합니다. 품절·판매 중지 상품은 새 캠페인 대상으로 선택할 수 없습니다.

여러 스토어 중 하나만 0개라면 상품 보관함의 스토어 필터와 주문·수집 기록의 같은 스토어 이력을 확인합니다. 전체 수집은 다른 연결이 성공해도 실패 수를 함께 표시합니다.

## IP가 등록되지 않았다고 나와요

표시 예: **현재 호출 IP가 네이버에 등록되어 있지 않습니다.**

현재 PC에서 네이버로 나가는 공인 IP를 확인해 커머스 API 센터의 해당 애플리케이션에 등록합니다. 집 Wi-Fi, 핫스팟, VPN 전환 뒤에는 IP가 달라질 수 있습니다. PC의 `192.168.x.x` 같은 내부 IP나 오래된 공인 IP를 그대로 등록하지 않습니다.

> 현재 PC의 공인 IP와 네이버 연결 오류를 확인해줘. 키는 출력하지 마.

등록 후 다시 수집해서 성공 여부를 확인합니다. 자격증명을 다시 발급받아야 한다고 먼저 판단할 필요는 없습니다.

## 네트워크 차단 또는 시간 초과가 나와요

| 오류 | 의미와 다음 조치 |
|---|---|
| EACCES/EPERM, 앱 실행 환경이 네트워크 접근을 차단 | 네이버에 도달하기 전 실행 권한·네트워크 제한 문제. Codex에서 네트워크 접근이 허용된 환경으로 서버 재시작을 요청하거나 Windows에서 stop.bat 후 start.bat 직접 실행 |
| 네이버 연결 시간이 초과 | 인터넷·핫스팟 연결 상태 확인 후 재시도 |
| 네이버 서버 주소를 찾지 못함, DNS | 인터넷·DNS 상태 점검 후 재시도 |
| HTTP 상태·API 오류 코드 | 해당 키의 API 권한과 네이버 설정 확인. 오류 문구를 Codex에 전달 |
| Client Secret 형식 오류 | 연결 설정에 입력한 Secret이 정확한지 확인. 채팅에 값을 붙여넣지 않기 |

2026-09-05에는 IP 등록이 정상이어도 Codex의 제한된 실행 환경에서 시작한 서버가 EACCES를 반환했습니다. 당시 앱이 이를 일반 시간 초과로 표시했고, 오류 안내 수정과 서버 재시작으로 해결했습니다. 같은 현상이면 핫스팟 장애라고 단정하지 말고 실행 환경도 함께 확인합니다. 방화벽 전체를 끄는 방식으로 해결하지 않습니다.

## 상품 수집은 되는데 주문이 없어요

최근 **수집 완료** 이력이 있는지 먼저 확인합니다. 최초 주문 수집은 최근 24시간의 변경 내역을 조회하므로 이전에 생성된 모든 주문이 자동으로 보이는 것은 아닙니다. 전체 누적 주문 목록을 보장하는 조회가 아닙니다.

조회 구간에 변경 주문이 없으면 0건이 정상입니다. 앱은 네이버가 데이터 배열 없이 반환하는 정상 빈 응답도 처리합니다. 오래된 서버에서 **네이버 주문 변경 응답 형식을 확인하세요**가 나온다면 서버를 재시작해 수정된 코드를 적용합니다. 계속되면 Codex에 응답 형식 점검을 요청합니다.

상품·주문 전체 수집은 상품 저장 후 주문 조회를 수행합니다. 따라서 주문 단계가 실패했어도 이미 성공한 상품 수집 결과는 남아 있을 수 있습니다. 최신 성공 위치와 각 단계의 결과를 구분합니다.

## 수집 중에서 멈췄거나 이미 수집 중이라고 나와요

같은 스토어의 수집을 중복 실행하지 않도록 잠금이 있습니다. 현재 작업이 끝날 때까지 기다립니다. 프로세스가 비정상 종료됐다면 잠금 만료에 최대 10분이 걸릴 수 있습니다.

버튼을 반복해서 누르거나 DB의 잠금 정보를 직접 지우지 말고, Codex에 진행 중인 실행과 마지막 기록을 확인해달라고 요청합니다. 오래된 실행 중 기록은 다음 정상 수집에서 실행 중단으로 정리됩니다.

## 제작 요청을 눌렀는데 이미지가 안 생겨요

1. 상단 AI 상태가 **AI 로그인 필요**인지 확인합니다.
2. 필요하면 **연결 · 채널 → ChatGPT로 Codex 로그인**을 완료합니다.
3. **오늘 할 일**의 **AI 광고 제작 시작**을 누릅니다.
4. `logs.bat`에서 `AI` 로그를 확인합니다. 실패하면 화면의 오류 문구를 기준으로 다시 실행합니다.

수동 처리 문장 복사는 SDK 실행이 어려울 때 쓰는 예비 기능입니다. **SNS 본문**에 요청 문장을 넣었다면 삭제하거나 제작된 광고 문구로 교체하고 저장합니다.

## 대기 요청이 없다고 나와요

| 가능한 상황 | 할 일 |
|---|---|
| 이미 처리돼 이미지와 시안이 저장됨 | 새로고침 후 결과 검토 |
| 캠페인만 만들고 제작 요청은 누르지 않음 | 해당 캠페인에서 **AI 광고 제작 시작** |
| 로그인 전에 요청을 저장함 | ChatGPT 로그인 후 오늘 할 일의 AI 실행 버튼 선택 |
| 요청 후 본문·방향을 수정·저장함 | 이전 요청이 오래된 버전으로 처리될 수 있으므로 최신 버전으로 다시 요청 |
| 새 결과가 필요함 | 캠페인 제목 또는 복사한 캠페인 ID와 원하는 수정 사항을 채팅으로 요청 |

**제작 중**은 검토 전 상태를 뜻합니다. 이미지가 이미 생성됐어도 검토 전이면 계속 ‘제작 중’입니다. 같은 결과가 있는데 버튼을 다시 누르면 새 제작 요청이 될 수 있으므로 먼저 확인합니다.

## Codex는 저장했다고 하는데 화면에는 안 보여요

1. 미저장 편집 내용을 별도 복사하거나 저장합니다.
2. 앱 오른쪽 위 **새로고침**을 누릅니다.
3. 캠페인 목록에서 의도한 제목을 선택합니다.
4. 창이 좁으면 아래로 내려 이미지 미리보기를 확인합니다.
5. 계속 안 보이면 Codex에 캠페인의 저장된 이미지·시안과 이미지 파일 응답을 확인해달라고 요청합니다.

서버 재시작 후 기존 화면의 요청 토큰이 오래됐다는 오류가 날 수 있습니다. 페이지를 다시 불러온 후 재시도합니다. 오류 배너만 계속 남아 있으면 미저장 내용을 보존한 뒤 브라우저 전체 새로고침을 사용합니다.

## 다른 작업에서 수정됐다는 오류가 나와요

앱과 Codex가 같은 캠페인을 다른 버전으로 편집했을 수 있습니다. 현재 작성 중인 문구를 별도 보관하고 새로고침한 뒤 최신 결과에 다시 적용합니다. Codex에게도 최신 brief를 읽고 적용하도록 요청합니다. 오래된 결과를 강제로 덮어쓰지 않습니다.

## 검토 완료 버튼이 비활성화되거나 실패해요

1. 본문과 이미지가 모두 있는지 확인합니다.
2. **수정 내용 저장**을 누릅니다. 이미지 파일 선택만으로는 적용이 완료되지 않습니다.
3. 상품 정보 확인란에 체크합니다.
4. **검토 완료로 표시**를 누릅니다.

상품 가격·판매 상태가 바뀌었다면 현재 상품으로 새 캠페인을 만듭니다. 확인 체크 없이 검토 완료로 넘어갈 수 없습니다. 이미 검토했던 캠페인도 수정·저장하면 다시 검토해야 합니다.

## 다운로드나 게시가 안 돼요

처음 게시하는 경우 [SNS 채널 로그인과 게시](social-channels.md)에서 채널별 전용 브라우저 로그인부터 진행합니다.

| 상황 | 확인할 내용 |
|---|---|
| 이미지 저장 버튼이 없음 | 검토 완료 상태에서 나타남 |
| 파일이 어디 저장됐는지 모름 | 브라우저 다운로드 목록 확인. Codex용 게시 파일 준비는 로컬 data/exports 경로 확인 |
| 전용 브라우저가 열리지 않음 | 화면을 새로고침해 최종 상태를 확인합니다. `브라우저 여는 중`이 1분 이상 유지되면 `stop.bat`으로 서버를 종료하고 Windows 탐색기에서 `start.bat`을 다시 실행합니다. 그 뒤 **전용 브라우저 로그인**을 다시 누릅니다. |
| `ERR_NETWORK_ACCESS_DENIED` 또는 제한된 네트워크 환경 | 서버가 Codex의 제한된 터미널에서 시작되어 SNS 브라우저도 외부 접속을 차단받은 상태입니다. `stop.bat` 후 탐색기에서 `start.bat`을 직접 실행합니다. 방화벽을 끄거나 SNS 비밀번호를 다시 설정할 문제는 아닙니다. |
| Playwright assertion 또는 브라우저가 즉시 종료 | 앱이 현재 설치된 Chrome을 우선 사용합니다. 계속되면 `data/runtime/instagram-worker.log`를 Codex에 점검 요청합니다. 손상된 프로필은 삭제하지 말고 별도 이름으로 백업한 뒤 새 로그인 프로필을 만듭니다. |
| 로그인 대기에서 멈춤 | 열린 전용 브라우저에서 로그인·추가 인증 완료. 10분이 지나면 다시 시작 |
| 만들기·다음·공유 버튼을 찾지 못함 | Instagram 화면 변경 가능. 직접 게시 후 선택자 수정을 요청 |
| Threads `role="dialog"` 또는 본문 입력란 시간 초과 | 이전 worker가 모달 작성기만 찾던 오류입니다. 0.5.0 최신 코드로 서버를 재시작하면 인라인 작성기도 처리합니다. 재시도 전 실제 Threads에 게시됐는지 확인합니다. |
| 실패가 떴지만 공유 버튼까지 진행됨 | 재시도하지 말고 실제 피드부터 확인해 중복 게시 방지 |
| 미리보기와 실제 Instagram에서 잘리는 범위가 다름 | 실제 게시 화면에서 이미지 자르기와 글자를 확인. 필요한 비율의 시안 수정 요청 |
| 영상 파일 업로드가 안 됨 | 앱은 PNG·JPEG·WebP 이미지 1장만 지원 |
| 게시물 주소가 거부됨 | 프로필 주소가 아닌 채널별 실제 게시물 주소인지 확인. Threads는 `/@계정/post/코드/`와 `/share/코드/`를 모두 허용 |
| 게시 기록 후 편집이 막힘 | 현재 앱은 게시 기록을 고정. 후속 콘텐츠는 새 캠페인 사용 |

Playwright 완료 메시지와 실제 피드 확인을 구분합니다. 실제 게시물 주소를 기록해야 캠페인이 게시 기록 상태가 됩니다. 자동 게시 기능이 실패한 환경에서는 받은 이미지·본문으로 직접 게시할 수 있습니다.

Threads에서 500자 오류가 나면 공통 본문을 500자 이하로 줄이고 저장한 뒤 다시 검토합니다. 밴드에서 게시 대상 오류가 나면 **연결 · 채널**의 밴드 홈 주소가 `https://band.us/band/숫자` 형식인지 확인합니다. Threads와 밴드는 0.3.0에서 새로 추가돼 실제 계정 UI에 따라 선택자 보완이 필요할 수 있습니다.

## AI 로그인 또는 생성이 실패해요

- **API 키 로그인**: 별도 API 요금을 막기 위해 자동 실행이 차단됩니다. [AI 자동화 문서](ai-automation.md)의 로그아웃 후 ChatGPT 로그인 절차를 따릅니다.
- **사용량 제한**: 구독 사용량이 다시 허용될 때 대기 요청을 재실행하거나 수동 처리합니다.
- **광고 이미지를 만들 Chromium 없음**: Chrome 또는 Edge 설치를 확인합니다.
- **PC 재부팅으로 중단됨**: 앱 재실행 후 같은 대기 작업을 다시 시작합니다.

로컬 앱은 API 키나 별도 이미지 API로 자동 전환하지 않습니다. 생성 실패 시 기존 카피, 이미지, 대기 요청은 보존됩니다.

## 데이터가 없어 보이거나 이미지가 깨져요

먼저 지금 연 폴더가 `codex_version`인지, 같은 PC와 포트인지 확인합니다. 상품·주문 화면의 스토어 필터가 의도한 연결인지 확인하고, 다른 버전 앱을 열지 않았는지 확인합니다.

이미지가 깨지면 외부 상품 사진 URL인지, 로컬 `data/assets` 파일인지 구분해 확인합니다. DB만 다른 PC로 복사하고 이미지 폴더를 빠뜨렸을 수도 있습니다. `.env`나 DB를 새로 만들거나 기존 파일을 지우지 말고 먼저 [백업·복원 절차](user-guide.md#데이터-보관과-복원)를 확인합니다.
