# 의사결정 기록

## 2026-09-05 — 독립 운영 버전

사용자는 Antigravity에서 작업 중인 `local_version`을 유지하고 `codex_version`에 Codex 전용 개발을 요청했습니다. 다른 버전의 소스·데이터·세션을 수정하거나 자격증명을 자동 이관하지 않습니다.

## 구독 AI와 일반 프로그램의 역할

네이버 호출·상태 저장·백업에는 AI 추론을 사용하지 않습니다. 0.5.0부터 카피와 리서치는 공식 Codex SDK를 별도 로컬 worker에서 실행합니다. SDK가 Codex CLI의 ChatGPT 로그인을 공유하므로 화면에서 버튼으로 시작할 수 있습니다. API 키 로그인은 별도 요금 가능성 때문에 자동 작업에서 차단합니다. 광고 이미지는 추가 이미지 API 대신 로컬 Chromium 템플릿으로 렌더링합니다.

## 런타임 최소화

Node 24의 SQLite를 사용해 서버·CLI가 같은 데이터에 접근하게 합니다. 네이버 전자서명용 bcryptjs만 외부 의존성으로 설치합니다. Next.js·Firebase를 복제하지 않아 실행과 데이터 보관을 단순하게 유지합니다. 기존 캠페인 도메인의 상품·출처·검토 개념은 참고합니다.

## 실제 게시와 파일 준비 구분

초기에는 검토한 콘텐츠의 파일 준비와 게시 결과 기록만 구현했습니다. 사용자 요청에 따라 `local_version`의 아이디어를 참고해 `codex_version` 전용 Playwright 프로필과 게시 작업을 추가했습니다. 다른 버전의 세션은 보안상 복사하지 않으며 최초 로그인을 새로 수행합니다. 최신 검토본과 즉시 공유 확인이 있어야 자동 게시가 시작됩니다. 웹 완료 메시지와 실제 피드·게시 URL 확인은 구분하고 자동 재시도하지 않습니다.

Meta 개발자 앱과 공개 이미지 호스팅이 필요한 공식 API 대신 로컬 브라우저 방식을 선택했습니다. 소규모 단일 계정 검증에서 설정과 비용을 줄일 수 있지만 Instagram 웹 화면 변경과 보안 확인에 영향을 받습니다.

## 데이터 범위

초기 운영 DB는 비어 있습니다. 상품 등록과 테스트 데이터 생성은 구분하며 테스트는 별도 DB에서만 실행합니다. 마케팅 작업에 불필요한 주문 수취인 개인정보는 저장하지 않습니다. 반복 판매·배송 처리 시스템으로 확장하려면 해당 업무 범위를 다시 설계합니다.

## 2026-09-06 — 단계형 UI와 멀티 연결

사용자가 반복 운영의 시작점을 쉽게 찾도록 별도 마법사보다 현재 저장 상태에서 다음 행동을 계산하는 **오늘 할 일** 화면을 기본으로 선택했습니다. 상세 화면은 유지해 숙련 사용자가 상품·주문·캠페인·연결로 바로 이동할 수 있습니다.

네이버 연결은 `storeId`가 상품·주문·체크포인트의 namespace가 되도록 여러 레코드로 저장합니다. 기존 단일 `.env` 연결은 처음 한 번만 이관해 운영 데이터를 깨뜨리지 않습니다. 연결 삭제 대신 사용 해제를 제공해 과거 상품·주문·수집 이력을 보존합니다.

SNS는 공통 worker 상태와 채널별 어댑터로 확장했습니다. Instagram의 검증된 프로필 경로는 유지하고 Threads와 밴드는 별도 프로필을 만듭니다. 채널 간 로그인 세션을 복사하지 않습니다. 캠페인은 게시 대상을 먼저 선택하고 실제 URL을 채널별로 기록합니다. 일부 채널 게시 후에는 이미 게시된 내용과 로컬 확정본이 달라지는 문제를 막기 위해 편집을 잠급니다.
